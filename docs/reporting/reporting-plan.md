# Reporting planning brief

**Owner:** Reporting Agent. **Reviewers:** Analytics, Security, UX, QA. **Status:** Proposed planning baseline. **Version:** 0.1. **Date:** 2026-10-14.

Propose organization summary, learning progress, assessment outcome, center operations, and synchronization health reports. PM selects P0 reports based on the presentation narrative. Report previews belong to the core proposal; working downloads and exact formats remain open.

Each report specification states audience, intended decision, authorized scope, filters, date interval/basis, timezone, fields, grouping, KPI definitions, generation time, data-as-of cutoff/version, freshness/coverage, and synthetic-data label. Empty and incomplete reports require explicit messages.

PDF, CSV, and XLSX are candidate formats to assess in Phase 3. A preview must not imply that an unsupported format downloads successfully. Scheduled report delivery is outside the current prototype baseline.

Use shared Analytics definitions and snapshot semantics. For the same scope, filters, period, and cutoff, report totals must match the dashboard. Security reviews individual-detail visibility and export scope; QA plans reconciliation and negative access cases.

Future outputs include the report catalogue, audience/format matrix, layouts, field mapping, export capability decision, expected totals, and report demonstration script.

The subsequent [reporting strategy](../reporting-strategy.md) specifies the eight user-required reports and proposed scheduled reporting. It extends this initial brief at documentation level; working downloads and automated delivery remain future implementation choices.
